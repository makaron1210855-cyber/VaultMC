# План 9.0 — стабилизация после 1.0

Цель: довести до конца то, что начато в 6.x–8.x и не проверено в игре, убрать временные куски, которые по CLAUDE.md должны уйти после 1.0, и включить облако миров. Новые большие функции — в 10.0.

Состояние кода проверено 20.11.2026 по репозиторию (не по памяти). Где расхождение с CLAUDE.md — указано.

## Этап 1. Проверка в игре (без новых функций)

Проверки делаем на двух ПК (или ПК + второй аккаунт с другим провайдером). Результаты записываем в CLAUDE.md, раздел «Что не доделано / не проверено».

1.1. **e4mc при `hostEnabled = false`.** Код: `core/lanworld.py:71` `set_e4mc_host` пишет строку в конфиг e4mc. Проверка: обычный «Играть» (без комнаты) — в логе e4mc нет создания адреса, в `saves` нет лишних строк. Если адрес создаётся — править `set_e4mc_host` или путь запуска.

1.2. **Вход по коду комнаты между двумя ПК.** Хозяин «Открыть мир для друзей» → код 6 знаков; гость «Зайти к другу» → код. Проверить: `GET /api/room/<код>` (старый путь) и `POST /api/room` с `action: lookup` (новый). Ожидание: гость попадает в мир без дружбы.

1.3. **Окно Windows-уведомлений о заявках.** `core/winnotify.py`. Проверка: заявка от второго аккаунта при свёрнутом лаунчере → окно появляется, клик открывает `vaultmc://friends`. Если окна нет — запасной `flash_window` должен мигнуть панелью задач; записать, что именно видно.

1.4. **Светлая тема на всех страницах.** Пройти все вкладки (`web/js/pages/*.js`) в `config.theme = light`, скриншоты. Исправлять только `rgba(var(--ov), …)` и явные белые/чёрные цвета в `web/css/app.css`.

**Готово, когда:** все четыре пункта отмечены в CLAUDE.md как «проверено» или заведена задача с конкретным багом.

## Этап 2. Убрать временные хвосты после 1.0

Перед удалением — порог версии. Решение владельца: какую версию лаунчера считаем последней поддерживаемой (предложение: 7.0.0 и новее). Старые лаунчеры по статистике падений (`core/crashstats.py`) не видно — только по согласию пользователей, поэтому порог ставим по дате и по твёрдому правилу «обновление обязательно».

2.1. **Ретранслятор: режим `HOST` без ключа.**
- Сервер: `server/relay/relay.py:234` (ветка `cmd == "HOST"`), строка 12 в справке протокола.
- Клиент: `core/relay.py:124` — запасной вызов `_ask("HOST", …)` для старых VPS. Его тоже убрать, если VPS обновлён (он уже обновлён 17.11.2026).
- Удалить ветку, обновить тесты `tests/test_relay.py`, залить на VPS (`/opt/vaultmc-relay/relay.py`, служба `vaultmc-relay`, старую копию оставить как `.bak`).
- Ожидание: `HOST` без ключа даёт ошибку; `HOST2` и `JOIN/CHECK` работают.

2.2. **Старый поиск комнаты `GET /api/room/<код>`.**
- Сервер: `server/worker.js:19` (справка), `server/worker.js:873` (комментарий «убрать после 1.0»).
- Удалить маршрут. Пока он есть, блок по коду обходится (см. 6.4.20 в CLAUDE.md).
- Проверить: тест на блок по коду через `lookup` проходит, GET отдаёт 404.

2.3. **Зеркало друзей в KV `friends:<ник>`.**
- Сервер: `server/worker.js:695` (перенос при первом обращении), `:820` (удаление при смене ника), `:829` (запись копии). Копия нужна только для отката — откат к 6.x давно не актуален.
- Порядок: сначала перестать писать копию (`:829`), подождать 1 месяц, затем удалить перенос и чтение (`:695`) и очистку (`:820`). Удалить ключи в KV, которые остались, одноразовым скриптом с лимитом KV-записей (бесплатно ~1000 в сутки — правило из CLAUDE.md «экономить записи»).
- Проверка: `tests/` (серверные тесты) проходят; перенос друзей из KV у старого аккаунта больше не нужен — проверить на тестовом нике, у которого есть друзья только в KV.

**Готово, когда:** в `worker.js` и `relay.py` нет строк «убрать после 1.0»; CLAUDE.md обновлён.

## Этап 3. Облако миров (этап 3 плана 8.0)

**Расхождение с CLAUDE.md:** там написано «R2 не включён, облако отвечает 503». Но в `server/wrangler.jsonc:17` привязка `r2_buckets` уже раскомментирована. Значит, код и конфиг готовы; нужно проверить, что бакет `vaultmc-worlds` создан и последний деплой прошёл с привязкой.

3.1. Проверить в панели Cloudflare: бакет `vaultmc-worlds` существует, закрытый доступ. Команда `npx wrangler deploy` из папки `server`.
3.2. Проверить `GET /api/worlds` (или `/api/status`, где `worlds: env.WORLDS ? … : null`, `server/worker.js:73`) — должно вернуть не `null`.
3.3. Сквозной тест на реальном мире: загрузка (`server/worlds.js`, multipart по 16 МБ), скачивание, корзина на 7 дней, смена владельца не теряет миры.
3.4. Лимиты и счётчики: `OPS_MONTH` 800 000 (`server/worlds.js:39`) — проверить, что счётчик не сбрасывается при деплое и что при близком к лимиту облако отвечает понятной ошибкой, а не падает.
3.5. Интерфейс: вкладка облака в лаунчере (`web/js/pages/` — найти по `worlds`), кнопки «Загрузить в облако» и «Скачать».

**Риск:** бесплатный тариф R2 — 1 млн операций класса A в месяц. Перед открытием для всех посчитать ожидаемую нагрузку по числу игроков; если не хватает — ограничить облако (например, только 1 мир на аккаунт на бесплатном тарифе).

**Готово, когда:** загрузка и скачивание реального мира проходят в проде; лимиты проверены; CLAUDE.md обновлён (убрать «пока R2 не включён»).

## Риски и порядок работ

| Порядок | Этап | Зачем именно в этом порядке |
|---|---|---|
| 1 | Проверка в игре (этап 1) | Если e4mc или вход по коду не работают, удалять старые маршруты рано |
| 2 | Облако миров (этап 3) | Нужен деплой, пока старые маршруты ещё работают |
| 3 | Удаление хвостов (этап 2) | Только после проверки 1 и 3 |
| 4 | p2p (этап 4) | Только проверка и текст, кода не трогаем |
| 5 | Свой сервер (этап 5) | Не зависит от остальных, можно параллельно |

Открытые вопросы для владельца:
- Порог версии лаунчера для удаления `HOST` и `GET /api/room` (этап 2).
- Нужен ли Linux для своего сервера (этап 5.3).
- Бесплатный тариф R2 или платный — от этого зависят лимиты облака (этап 3).

## Дополнения (добавлено 20.11.2026)

Д1. **Порог версии на сервере.** `server/worker.js` отказывает клиентам ниже 9.0.0 в `HOST2`, `lookup` и `offer` с кодом `update_required` («обновите лаунчер»). Нужен для этапа 2: без этого удаление `HOST` и `GET /api/room` сломает старые сборки молча.

Д2. **Лимиты в памяти → Durable Object.** Счётчики (неверный пароль, ники, скины, комнаты, 240 запросов/мин) сейчас в памяти объекта и сбрасываются при перезапуске. Перенести в SQLite объекта `Social`, как заявки (этап 4).

Д3. **Предрелизная проверка одной командой.** Скрипт: `compileall`, `node --check`, `node --test tests/`, `pytest`, проверка `I18N_EN`, поиск строк «убрать после 1.0» в `worker.js` и `relay.py`. Перед выпуском 9.0 обязателен. CI на GitHub Actions — отдельным решением, не проверено, есть ли он сейчас.

Д4. **Квоты облака миров.** Лимит миров на ник и суммарного объёма; загрузка с чужим `owner` отклоняется. Без этого один игрок может занять весь бакет.
